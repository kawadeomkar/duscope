# The external-input audit (P5-SEC-01): every call that reaches the filesystem
# by a path or a name in the code the binary is built from, and why each is
# safe: what reaches it, from whom, and what bounds or checks it. fs_allowlist.rs
# says which calls count and which code is read, and fails on a call this list
# does not hold or holds a different number of, and on an entry whose calls are
# gone. A new call is reviewed, then written here.
#
# Format: `## <file>`, then for each function a line
# `<function>: <call>[ xN][, <call>[ xN]]…` (`(item)` outside any function) and
# the reason on the indented lines below it.
#
# Who names what: "a person" is the user at the command line (flags, the
# environment, the configuration), whom the threat model does not guard against
# (SECURITY.md, "What is not protected"); "an agent" is an MCP client, whose
# paths go through crates/duscope-mcp/src/roots.rs and which names saved scans
# by id only; "the tree" is the scanned tree, anyone's; "a saved scan" is an
# index file, which may come from anyone when --trust names it.

## crates/duscope-core/src/clean.rs

clean_plan_until: fs::symlink_metadata
  Each item clean or duscope_delete names (a person's path, or the path a
  handle that verified names; an agent's only within --roots): an lstat, so the
  entry itself and never what a link leads to, whose (dev, ino) must match the
  handle's. Reads no contents and changes nothing.
overlap: fs::metadata
  The directories above each item of a plan, to find an item inside another the
  plan moves: a stat of each, as the path resolves. Reads no contents.

## crates/duscope-core/src/config.rs

load: fs::read_to_string
  The configuration file a person names (--config, DUSCOPE_CONFIG, else
  $XDG_CONFIG_HOME/duscope/config.toml); no MCP tool names one. Read whole and
  parsed as TOML: the user's own file, so not capped.

## crates/duscope-core/src/git.rs

repo_root: .exists()
  explain: `.git` in each directory above the path explained (a person's, or an
  agent's within --roots). A stat; what `.git` holds is read only through
  duscope_walk::read_regular, a regular file under a cap (DEV-154).
tracked_inside: .exists()
  The repository's `index` in the git directory found: a stat before its read,
  which goes through read_regular, 1 GiB at most (DEV-154).

## crates/duscope-core/src/handle.rs

create: DirBuilder::new, File::open, OpenOptions::new, fs::hard_link, fs::remove_file
  The handle key, made where none is, in the index directory (a person's
  --index-dir or DUSCOPE_INDEX_DIR, else the cache directory): the directory
  made 0700, 40 bytes read from /dev/urandom, the key written to a staged name
  with O_CREAT|O_EXCL and mode 0600 whatever the umask, linked into place (a key
  already there wins) and the staged name removed. No client path reaches it.
open: .metadata(), File::open, fs::symlink_metadata x2
  handle.key in the index directory: an lstat first (refused unless a regular
  file of this user's with no group or other bits), then opened and the opened
  file's (dev, ino) compared with the lstat's, so neither a link nor a file
  swapped in is read; 32 bytes and no more.

## crates/duscope-core/src/index/reader.rs

open: Connection::open_with_flags
  Every index file read: from the index directory (query/resolve.rs
  index_files: regular files named <id>.db), or a file --scan names that
  resolves inside it or that --trust names (query/resolve.rs trusted); never a
  client's path. Read-only and immutable, defensive, views and triggers off,
  the schema untrusted, limits lowered, and the schema and version checked
  before any row is read (SECURITY.md, Index files).

## crates/duscope-core/src/index/scanid.rs

## crates/duscope-core/src/index/writer.rs

build: Connection::open, File::open, OpenOptions::new
  The temporary index file scans/<id>.db.tmp-<pid> in the index directory:
  created empty with O_CREAT|O_EXCL and mode 0600 (no link followed, whatever
  the umask), filled by SQLite, then synced. The scan id names it; no client
  path reaches it.
write_file_until: fs::remove_file
  That temporary file, removed before a second build with the sort in memory.
write_in: DirBuilder::new, File::open, fs::remove_file, fs::rename
  The index directory's `scans`, made 0700 with each directory above it that
  is missing; the temporary file renamed to <id>.db, so a snapshot appears whole
  or not at all, and the directory synced; on a failure the temporary file is
  removed.
