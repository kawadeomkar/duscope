### Changed
- `scans --check` also tells whether the scanned tree changed since the scan. After checking the file for damage, it reads every directory the scan holds again (one `statx` on Linux, one `getattrlist` on macOS each) and compares the later of its modification and status-change times with the scan's: an entry added, removed or renamed, a mode or owner changed, or a directory gone makes the scan stale. A stale scan exits 1 with `index_stale` and a hint to rescan, its row printed with `structurally_stale: true`; a fresh one exits 0, and a damaged file still exits 5. The index directory, which every save writes to, is left out, so a scan of a tree that holds it can still check fresh. A file rewritten in place changes no directory, and is not seen.
